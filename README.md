# 🐾 PetCostTrack

**ระบบบันทึกและคำนวณค่าใช้จ่ายแฝงของคนเลี้ยงสัตว์**
Web Application สำหรับบันทึก จัดหมวดหมู่ และสรุปภาพรวมค่าใช้จ่ายในการเลี้ยงสัตว์เลี้ยง — ทั้งค่าใช้จ่ายหลักที่วางแผนไว้แล้ว และ **"ค่าใช้จ่ายแฝง"** ที่มักถูกมองข้าม พร้อมระบบแชร์ข้อมูลให้สมาชิกในครอบครัวที่ร่วมดูแลสัตว์เลี้ยงตัวเดียวกันเห็นภาพเดียวกัน

## ที่มาและปัญหา

ปัจจุบันการเลี้ยงสัตว์เลี้ยงในสังคมเมืองของไทยมีแนวโน้มเพิ่มขึ้นต่อเนื่อง โดยเฉพาะในกลุ่มคนวัยทำงานและครอบครัวรุ่นใหม่ที่มองสัตว์เลี้ยงเป็นสมาชิกในครอบครัว ผู้เลี้ยงส่วนใหญ่มักวางแผนงบประมาณเฉพาะค่าใช้จ่ายที่มองเห็นชัด เช่น ค่าอาหาร ค่าฉีดวัคซีน แต่ในความเป็นจริงยังมี **ค่าใช้จ่ายแฝง** อีกจำนวนมากที่เกิดขึ้นไม่สม่ำเสมอและมักถูกมองข้าม เช่น ค่ารักษาพยาบาลฉุกเฉิน ค่าซ่อมแซมข้าวของที่สัตว์เลี้ยงทำเสียหาย หรือค่าฝากเลี้ยง

ปัญหาหลักที่พบจากการวิเคราะห์กระบวนการทำงานปัจจุบันของผู้เลี้ยงสัตว์ มี 4 ข้อ:

1. **ไม่มีเครื่องมือบันทึกค่าใช้จ่ายที่ไม่ได้วางแผนไว้อย่างเป็นระบบ** — ทำให้ประเมินต้นทุนที่แท้จริงของการเลี้ยงสัตว์ต่ำกว่าความเป็นจริง
2. **ข้อมูลค่าใช้จ่ายกระจัดกระจายหลายช่องทาง** — เงินสด แอปธนาคาร แชท สมุดจด ไม่มีศูนย์กลางข้อมูลเดียว
3. **ไม่มีระบบแจ้งเตือนล่วงหน้า** สำหรับรายการที่เกิดซ้ำแต่ไม่บ่อย เช่น วัคซีนประจำปี ทำให้พลาดกำหนด
4. **ครอบครัวที่มีผู้ร่วมดูแลหลายคนไม่มีข้อมูลกลางร่วมกัน** — ทำให้ไม่ทราบยอดรวมที่แท้จริง และอาจซื้อของซ้ำซ้อนกัน

**PetCostTrack** ถูกออกแบบมาเพื่อแก้ปัญหาทั้ง 4 ข้อนี้โดยตรง ด้วยการเป็นศูนย์กลางข้อมูลเดียวที่รวบรวม จัดหมวดหมู่ และคำนวณสรุปค่าใช้จ่ายให้อัตโนมัติ พร้อมระบบแจ้งเตือนและระบบแชร์สิทธิ์การเข้าถึงข้อมูลให้สมาชิกในครอบครัว

## วัตถุประสงค์ของโครงงาน (Project Goals)

| เป้าหมาย | รายละเอียด |
|---|---|
| **Goal 1** | พัฒนา Web Application สำหรับรวบรวม บันทึก และจัดหมวดหมู่ค่าใช้จ่ายทั้งประจำและค่าใช้จ่ายแฝงในการเลี้ยงสัตว์ |
| **Goal 2** | สร้างระบบส่วนกลางที่ให้เจ้าของสัตว์เลี้ยงและผู้ร่วมดูแล (Co-caretaker) เข้าถึงและจัดการข้อมูลทางการเงินของสัตว์เลี้ยงร่วมกันได้ |
| **Goal 3** | ลดปัญหาการลืมชำระ/พลาดกำหนดค่าบริการสำคัญ ผ่านระบบตั้งรายการค่าใช้จ่ายที่เกิดซ้ำและการแจ้งเตือน |

|---|---|---|

## คุณสมบัติหลักของระบบ (Key Features)

### 📊 แดชบอร์ด (Dashboard)
- สรุป KPI: ยอดใช้จ่ายรวม, ยอดค่าใช้จ่ายแฝง, % งบประมาณที่ใช้ไป, จำนวนสัตว์เลี้ยง
- กราฟวงกลม (Doughnut Chart) แสดงสัดส่วนค่าใช้จ่ายแยกตามหมวดหมู่
- รายการค่าใช้จ่ายล่าสุด
- **ตัวกรองสัตว์เลี้ยง + เดือน/ปี** เลือกดูภาพรวมของสัตว์เลี้ยงตัวใดตัวหนึ่ง หรือเดือน/ปีที่ต้องการย้อนดูได้
- **เปรียบเทียบภาพรวมค่าใช้จ่าย** กับเดือน/ปีที่ผ่านมา พร้อมตัวเลข % เปลี่ยนแปลงขึ้น/ลง

### 🐶 จัดการสัตว์เลี้ยง (Pet Profile Management)
- เพิ่ม/แก้ไข/ลบโปรไฟล์สัตว์เลี้ยง พร้อม**อัปโหลดรูปภาพ** (jpg/png/webp, รูปใหญ่ถูกย่ออัตโนมัติให้ด้านยาวไม่เกิน 1280px, เก็บบน Supabase Storage bucket `pet-photos`)
- ระบุรายละเอียด: ชื่อ, ประเภท, สายพันธุ์ (แยกจากประเภท), เพศ, อายุ (**ปี + เดือน** เช่น 1 ปี 6 เดือน), น้ำหนัก, วันเกิด, วันที่รับเลี้ยง, หมายเลขไมโครชิป
- ฟิลด์บังคับกรอก **ชื่อ, ประเภท, เพศ, อายุ** (กรอกปีหรือเดือนอย่างน้อย 1 ช่อง) ส่วนที่เหลือกรอกหรือไม่กรอกก็ได้
- ตรวจค่าก่อนบันทึกพร้อมข้อความภาษาไทยใต้ช่อง: อายุและน้ำหนักกรอกค่าน้อยกว่า 0 ไม่ได้, เดือน 0–11, อายุไม่เกิน 150 ปี, น้ำหนักต้องมากกว่า 0 และไม่เกิน 999.99 กก.
- แสดง badge สิทธิ์ (Owner / Co-caretaker) ของสัตว์เลี้ยงแต่ละตัว
- **เก็บเข้าคลัง** (Archive) แทนการลบถาวรเมื่อสัตว์เลี้ยงเสียชีวิต/ย้ายไป แล้วย้อนดูได้ที่หน้าโปรไฟล์ (เฉพาะ Owner)

### 💸 ประวัติรายจ่าย (Expense History)
- บันทึกรายการค่าใช้จ่าย พร้อมระบุสัตว์เลี้ยง หมวดหมู่ จำนวนเงิน วันที่ และหมายเหตุ
- แยกประเภท **ค่าใช้จ่ายหลัก** และ **ค่าใช้จ่ายแฝง** อย่างชัดเจนที่ระดับฐานข้อมูล
- **แบ่งค่าใช้จ่าย 1 รายจ่ายให้สัตว์เลี้ยงหลายตัว** (Many-to-Many) พร้อมช่องกรอกจำนวนเงินให้แต่ละตัวและตรวจสอบผลรวมแบบ real-time
- **แนบไฟล์ใบเสร็จหลายไฟล์ต่อรายการ** (jpg/png/pdf ขนาดไม่เกิน 50MB/ไฟล์) ดู/ลบได้จากหน้าประวัติ
- **สร้างหมวดหมู่ค่าใช้จ่ายของตนเองเพิ่มเติมได้** (BR-07) จากฟอร์มเพิ่มรายจ่าย
- ตัวกรอง: ประเภทค่าใช้จ่าย, สัตว์เลี้ยง, หมวดหมู่
- แสดงยอดรวมตามเงื่อนไขที่กรองไว้

### 💰 งบประมาณ (Budgets)
- ตั้งงบประมาณรายเดือนแยกตามสัตว์เลี้ยงแต่ละตัว (BR-03: งบแยกตามเดือน จึงเริ่มนับใหม่ทุกวันที่ 1) และ **แก้ไข/ลบงบ** ได้ (เฉพาะ Owner)
- เปรียบเทียบยอดใช้จริงกับงบที่ตั้งไว้ พร้อม progress bar เตือนเมื่อใกล้ (เกิน 80%) / เกินงบ — ยอดใช้จริงมาจาก view `budget_summary_view` ซึ่งรวมส่วนแบ่งที่สัตว์ตัวนี้ได้รับจากรายจ่ายของตัวอื่นแล้ว ตรงกับแดชบอร์ด
- ตัวกรองดูงบประมาณตามสัตว์เลี้ยง / เดือน / ปี
- ทุกวันที่ 1 ระบบคัดลอกงบเดือนก่อนให้อัตโนมัติ (Stored Procedure `carry_over_monthly_budgets` ผ่าน pg_cron) งบที่ตั้งเองไว้แล้วไม่ถูกทับ

### 🔔 การแจ้งเตือน (Reminders)
- ตั้งรายการค่าใช้จ่าย/กิจกรรมที่เกิดซ้ำ (รายเดือน / รายปี) เช่น วัคซีนประจำปี ถ่ายพยาธิ
- ระบุวันครบกำหนด และ**เลือกจำนวนวันแจ้งเตือนล่วงหน้า**ของแต่ละรายการ (0–60 วัน ค่าเริ่มต้น 7 วัน)
- กด **"เสร็จแล้ว"** แล้วระบบตั้งรอบถัดไปให้อัตโนมัติ (+1 เดือน / +1 ปี ข้ามไปรอบแรกที่ยังไม่ผ่านถ้ากดช้า) ผ่าน RPC `complete_reminder()`
- ไฮไลต์รายการที่ถึงกำหนดหรือเลยกำหนดแล้ว — ตั้ง/แก้/ลบได้เฉพาะ Owner ส่วน Co-caretaker ดูได้อย่างเดียว
- แจ้งเตือน**ภายในแอป** (toast บนแดชบอร์ดตามจำนวนวันล่วงหน้าของแต่ละรายการ) + **อีเมล** ทุกวัน 07:00 น. (Edge Function `send-reminder-emails` เรียกโดย pg_cron — ต้องตั้งค่าตาม `supabase/functions/send-reminder-emails/README.md`)
- **คำเชิญเป็นผู้ร่วมดูแล** (Pet Invitations) โชว์บนหน้านี้พร้อมชื่อผู้เชิญ ให้ผู้ถูกเชิญตอบรับ/ปฏิเสธก่อนถึงได้สิทธิ์จริง (แสดงเฉพาะคำเชิญที่ยังไม่หมดอายุ)

### 👨‍👩‍👧 โปรไฟล์และครอบครัว (Profile & Family)
- แก้ไขข้อมูลส่วนตัว, เปลี่ยนรหัสผ่านโดยยืนยันตัวตนด้วยรหัส OTP ทางอีเมล
- **เชิญสมาชิกครอบครัวเป็นผู้ร่วมดูแลผ่านอีเมล** (เฉพาะ Owner ของสัตว์เลี้ยงตัวนั้น) และแสดงรายชื่อสมาชิกที่มีสิทธิ์เข้าถึงสัตว์เลี้ยงร่วมกัน
- ผู้ร่วมดูแลสูงสุด **3 คน** ต่อสัตว์เลี้ยง 1 ตัว (นับคำเชิญที่รอตอบรับด้วย) และคำเชิญ**หมดอายุใน 7 วัน** คำเชิญที่หมดอายุถูกลบทุกคืน
- ถอดสิทธิ์ผู้ร่วมดูแลแล้ว รายจ่ายที่เขาเคยบันทึกยังอยู่พร้อมชื่อผู้บันทึกเดิม (BR-06)
- แสดงจำนวนสัตว์เลี้ยงที่เป็นเจ้าของ พร้อมลิงก์ไปหน้าจัดการสัตว์เลี้ยง + คลังสัตว์เลี้ยงที่เก็บเข้าคลัง

### 🔐 ระบบสมาชิก (Authentication)
- สมัครสมาชิก / เข้าสู่ระบบ / ออกจากระบบ ผ่าน Supabase Auth (Email + Password)
- **ยืนยันอีเมลหลังสมัคร**: อีเมลยืนยันมีปุ่ม "ยืนยันอีเมล" ที่พาไปหน้า `confirm-email.html` ของเว็บ หน้านี้ยืนยันกับ Supabase เองแล้วแสดงผลชัดเจน (สำเร็จแล้วเข้าสู่ระบบให้ทันที / ลิงก์หมดอายุหรือใช้ไปแล้ว) และขออีเมลยืนยันใหม่ได้ทั้งจากหน้านี้และจากหน้าเข้าสู่ระบบ
- **ลืมรหัสผ่าน / เปลี่ยนรหัสผ่านด้วยรหัส OTP**: กด "ลืมรหัสผ่าน?" ที่หน้าเข้าสู่ระบบ (หรือ "เปลี่ยนรหัสผ่าน" ที่หน้าโปรไฟล์) → ระบบส่งรหัส OTP ไปที่อีเมล → กรอกรหัสพร้อมรหัสผ่านใหม่ที่หน้า `reset-password.html` (ไม่ต้องกดลิงก์ในอีเมล จึงไม่มีปัญหาลิงก์หมดอายุ/ถูกใช้ไปแล้ว)
- ผูกบัญชีผู้ใช้ใหม่เข้ากับข้อมูลตัวอย่าง (seed data) อัตโนมัติเมื่ออีเมลตรงกัน
- ป้องกันหน้าทุกหน้าไม่ให้เข้าถึงได้หากยังไม่ได้เข้าสู่ระบบ

## โครงสร้างฐานข้อมูล (Database Schema)

ออกแบบเป็นฐานข้อมูลเชิงสัมพันธ์ (Relational Database) บน PostgreSQL มีตารางหลัก 10 ตาราง:

| ตาราง | คำอธิบาย |
|---|---|
| `users` | ผู้ใช้งานระบบ (ชื่อ, อีเมล, บทบาทระดับบัญชี Owner/Co-caretaker, เชื่อมกับ Supabase Auth ผ่าน `auth_id`) |
| `pets` | โปรไฟล์สัตว์เลี้ยง (ชื่อ, ประเภท, สายพันธุ์, เพศ, น้ำหนัก, วันเกิด, วันที่รับเลี้ยง, ไมโครชิป, path รูปภาพ, สถานะเก็บเข้าคลัง) |
| `pet_access` | ตารางเชื่อม (Many-to-Many) ระหว่าง `users` และ `pets` — กำหนดว่าใครมีสิทธิ์อะไร (Owner/Co-caretaker) กับสัตว์เลี้ยงตัวไหน |
| `categories` | หมวดหมู่ค่าใช้จ่าย (เช่น อาหาร, วัคซีน, ค่ารักษาพยาบาลฉุกเฉิน) พร้อมประเภท "หลัก"/"แฝง" — ผู้ใช้สร้างหมวดหมู่ของตนเองเพิ่มได้ |
| `expenses` | รายการค่าใช้จ่าย ผูกกับสัตว์เลี้ยงหลัก ผู้บันทึก และหมวดหมู่ แยกประเภท "หลัก"/"แฝง" |
| `expense_pet_shares` | ตารางเสริม (additive) แบ่งรายจ่ายให้สัตว์เลี้ยงตัวอื่น — junction ระหว่าง `expenses` และ `pets` (Many-to-Many) |
| `receipts` | ไฟล์ใบเสร็จที่แนบกับรายการค่าใช้จ่าย (หลายไฟล์ต่อรายจ่าย รองรับ jpg/png/pdf) |
| `budgets` | งบประมาณรายเดือนของสัตว์เลี้ยงแต่ละตัว |
| `reminders` | รายการแจ้งเตือนที่เกิดซ้ำ ผูกกับสัตว์เลี้ยงและหมวดหมู่ |
| `pet_invitations` | คำเชิญเป็นผู้ร่วมดูแล (pending/accepted/declined) ที่ส่งจาก Owner ให้สมาชิกตอบรับ/ปฏิเสธ |

รวมถึง **View** `budget_summary_view` ที่คำนวณยอดใช้จริงเทียบกับงบที่ตั้งไว้แบบ derived attribute และ **Storage bucket** `pet-photos` (รูปสัตว์เลี้ยง, สร้างโดย migration `20260930000000_pet_photos.sql`) + `receipts` (ไฟล์ใบเสร็จ)

> **หมายเหตุออกแบบ Many-to-Many:** ตามผลสำรวจผู้ใช้ (ข้อ 17.3) ที่ต้องการผูก 1 Transaction กับสัตว์เลี้ยงหลายตัว ระบบใช้ตาราง junction `expense_pet_shares` (Expense Allocation) เก็บส่วนแบ่งให้สัตว์เลี้ยงตัวอื่น อย่างไรก็ตาม `expenses.pet_id` เดิมยังถูกเก็บไว้เป็น "สัตว์เลี้ยงหลัก" ของรายจ่ายนั้น เพราะ RLS และนโยบายสิทธิ์อ้างอิง `pet_id` — เมื่อดูสรุปของสัตว์เลี้ยงตัวใดตัวหนึ่ง (แดชบอร์ดที่กรองสัตว์เลี้ยง และ `budget_summary_view`) ยอดของสัตว์ตัวนั้น = รายจ่ายที่เป็นตัวหลัก หักส่วนที่แบ่งให้ตัวอื่น + ส่วนแบ่งที่ได้รับจากรายจ่ายของตัวอื่น (ดูรายละเอียดใน `supabase/migrations/20260913000000_expense_pet_shares.sql` และ `20260922000100_security_hardening.sql`)

### ตรรกะที่ทำงานในฐานข้อมูล
- **Trigger 4 ตัว**: `on_auth_user_created` (สร้างแถว users ตอนสมัคร), `trg_set_expense_recorder_role` (บันทึกบทบาทผู้บันทึก), `trg_prevent_non_owner_archive` (เก็บเข้าคลังได้เฉพาะ Owner), `trg_guard_pet_access_update` (กันแก้สิทธิ์ผิดวิธี)
- **Function / RPC**: งานที่ต้องทำหลายตารางในคำสั่งเดียว เช่น `create_pet_with_owner`, `invite_co_caretaker`, `accept_pet_invitation`, `complete_reminder` และฟังก์ชันตรวจสิทธิ์ที่ RLS เรียก (`user_has_pet_access`, `user_is_pet_owner` ฯลฯ)
- **Stored Procedure 4 ตัว** (`20261010131150_maintenance_procedures.sql`): `carry_over_monthly_budgets`, `rollover_completed_reminders`, `purge_expired_invitations` และ `run_daily_maintenance` ที่เรียกทั้ง 3 ตัว
- **pg_cron** (`20261013100300_schedule_daily_jobs.sql`): รัน `run_daily_maintenance()` ทุกวัน 00:05 น. และเรียก Edge Function อีเมลทุกวัน 07:00 น. (เวลาไทย)

### แนวคิดการควบคุมสิทธิ์
ระบบไม่ได้เก็บ "เจ้าของ" ไว้เป็นคอลัมน์ตรงๆ ในตาราง `pets` แต่ใช้ตารางเชื่อม `pet_access` (M:N) เพื่อให้สัตว์เลี้ยงหนึ่งตัวมีได้ทั้ง Owner และ Co-caretaker หลายคน และผู้ใช้หนึ่งคนดูแลสัตว์เลี้ยงได้หลายตัว การอนุญาต/ปฏิเสธการเข้าถึงข้อมูลทั้งหมด (อ่าน/เพิ่ม/แก้ไข/ลบ) บังคับใช้ที่ระดับฐานข้อมูลด้วย PostgreSQL **Row Level Security (RLS) Policies** (ดูรายละเอียดทั้งหมดในโฟลเดอร์ `supabase/migrations/`) ทำให้ต่อให้ Frontend ถูกดัดแปลง ผู้ใช้ก็ยังไม่สามารถมองเห็นหรือแก้ไขข้อมูลของสัตว์เลี้ยงที่ตนเองไม่มีสิทธิ์ได้

## สิทธิ์การใช้งาน (Roles & Permissions)

สิทธิ์ในระบบมี 2 ระดับ: **บทบาทระดับบัญชี** (`users.role`) และ **บทบาทต่อสัตว์เลี้ยงแต่ละตัว** (`pet_access.access_role`) — ผู้ใช้คนเดียวอาจเป็น Owner ของสัตว์เลี้ยงตัวหนึ่ง และเป็น Co-caretaker ของอีกตัวหนึ่งพร้อมกันได้ สรุปสิทธิ์การใช้งานจริงที่บังคับใช้ผ่าน RLS:

| การกระทำ | Owner (ของสัตว์เลี้ยงตัวนั้น) | Co-caretaker |
|---|---|---|
| ดูข้อมูลสัตว์เลี้ยง/ค่าใช้จ่าย/งบประมาณ/การแจ้งเตือน | ✅ | ✅ |
| เพิ่มสัตว์เลี้ยงใหม่ (กลายเป็น Owner ของตัวนั้นทันที) | ✅ | ✅ |
| แก้ไขโปรไฟล์สัตว์เลี้ยง | ✅ | ✅ |
| ลบโปรไฟล์สัตว์เลี้ยง / เก็บเข้าคลัง | ✅ | ❌ |
| บันทึกรายการค่าใช้จ่ายใหม่ | ✅ | ✅ |
| แก้ไข/ลบรายการค่าใช้จ่าย (ทุกรายจ่ายของสัตว์เลี้ยงตัวนั้น / เฉพาะรายจ่ายที่ตนเองบันทึกไว้) | ✅ | ✅ |
| จัดการครอบครัว: เชิญ/นำออกผู้ร่วมดูแล (เฉพาะ Owner ของสัตว์เลี้ยงตัวนั้น) | ✅ | ❌ |
| ตั้ง/แก้ไข/ลบงบประมาณ | ✅ | ❌ |
| ตั้ง/แก้ไข/ลบการแจ้งเตือน | ✅ | ❌ |

## การติดตั้งและใช้งาน (Getting Started)

โปรเจกต์นี้เป็นเว็บไซต์ static (ไม่มีขั้นตอน build) เชื่อมต่อกับฐานข้อมูล/บริการหลังบ้านผ่าน [Supabase](https://supabase.com)

### 1. เตรียมโปรเจกต์ Supabase
1. สร้างโปรเจกต์ใหม่ที่ [supabase.com](https://supabase.com)
2. สร้าง Storage bucket ชื่อ `receipts` (private) ใน Dashboard → Storage
3. รัน migration ทั้งหมดตามลำดับ: `supabase link --project-ref <ref>` แล้ว `supabase db push` (หรือเปิด **SQL Editor** แล้วรันไฟล์ในโฟลเดอร์ `supabase/migrations/` เรียงตามชื่อไฟล์) เพื่อสร้างตาราง, ข้อมูลตัวอย่าง (seed data), RLS Policies, Trigger, Function, Procedure และ bucket `pet-photos`
   - ก่อนไฟล์ `20261013100300_schedule_daily_jobs.sql` ต้องสร้าง Vault secret 2 ค่าตามคำอธิบายในหัวไฟล์นั้น
4. Authentication → Emails → Templates:
   - **Confirm signup**: Subject `ยืนยันอีเมลเพื่อเริ่มใช้งาน PetCostTrack` และวางเนื้อหาจาก `supabase/templates/confirm_signup.html` (ปุ่ม "ยืนยันอีเมล" พาไปหน้า `confirm-email.html` ของเว็บ)
   - **Reset Password**: วางเนื้อหาจาก `supabase/templates/reset_password.html` (อีเมลจะมีรหัส OTP `{{ .Token }}` แทนลิงก์)
   - ตั้ง **Site URL** เป็นโดเมนของเว็บใน Authentication → URL Configuration (ถ้าต้องการให้ปุ่มยืนยันอีเมลพากลับมาที่เครื่องตอนทดสอบ เช่น `http://127.0.0.1:5500` ให้เพิ่ม `http://127.0.0.1:5500/**` ใน **Redirect URLs** ด้วย)
5. Deploy Edge Function แจ้งเตือนทางอีเมลตาม `supabase/functions/send-reminder-emails/README.md`

### 2. ตั้งค่าการเชื่อมต่อ
1. คัดลอกไฟล์ `js/config.js` เป็น `js/config.env.js` (ถ้ายังไม่มี)
2. ใส่ค่า **Project URL** และ **anon public key** ของโปรเจกต์ Supabase ของคุณ (ดูได้จาก Project Settings → API):

```js
var CONFIG = {
    SB_URL: 'https://YOUR-PROJECT.supabase.co',
    SB_KEY: 'YOUR-ANON-KEY',
    REST: 'https://YOUR-PROJECT.supabase.co/rest/v1',
    AUTH: 'https://YOUR-PROJECT.supabase.co/auth/v1'
};
```

> anon key ปลอดภัยที่จะฝังไว้ฝั่ง client เพราะสิทธิ์การเข้าถึงข้อมูลจริงถูกควบคุมด้วย Row Level Security ที่ฐานข้อมูล ไม่ใช่ตัว key เอง

### 3. รันโปรเจกต์
เนื่องจากไม่มีขั้นตอน build ใดๆ สามารถเสิร์ฟไฟล์แบบ static ได้เลย เช่น:

```bash
npx serve .
# หรือ
python3 -m http.server 5500
```

แล้วเปิดเบราว์เซอร์ไปที่ `login.html` เพื่อสมัครสมาชิก/เข้าสู่ระบบ

### 4. Deploy ขึ้น Production
โปรเจกต์ตั้งค่าให้ deploy บน [Vercel](https://vercel.com) ไว้แล้ว (ดู `vercel.json`) เพียงเชื่อมต่อ repository เข้ากับ Vercel ก็ deploy ได้ทันที (ไม่ต้องตั้งค่า Build Command เพราะเป็น static site)

| ระบบ E-Commerce | มีความซับซ้อนเกินไปและไม่ตรงวัตถุประสงค์หลักของระบบบันทึกบัญชี |

## ผลสำรวจผู้ใช้และแผนพัฒนาต่อ (Roadmap)

ก่อนเริ่มพัฒนา ทีมได้เก็บข้อมูลจากแบบสัมภาษณ์ผู้เลี้ยงสัตว์จำนวน **23 คน** เพื่อยืนยันและปรับปรุง Requirement ให้ตรงกับความต้องการจริง ผลสรุปที่สำคัญ:

- เลี้ยงสัตว์ 1 ตัว 65.2% / มีผู้ร่วมดูแลค่าใช้จ่าย 87% / **73.9% ไม่เคยบันทึกค่าใช้จ่ายอย่างเป็นระบบมาก่อน**
- ฟีเจอร์ที่ผู้ใช้เห็นว่าสำคัญที่สุด (โหวตสูงสุด): **Expense Tracking**, **Pet Profile Management**, **User Authentication**
- ผู้ใช้ 82.6% เห็นว่าควรแยกโครงสร้าง "ค่าใช้จ่ายหลัก" กับ "ค่าใช้จ่ายแฝง" ที่ระดับฐานข้อมูลจริง — ระบบปัจจุบันออกแบบตามแนวทางนี้แล้ว (คอลัมน์ `expense_type`)
- ช่องทางแจ้งเตือนที่ต้องการมากที่สุดคือการผสมผสานมากกว่า 1 ช่องทาง โดยเฉพาะ **LINE Notify** และอีเมล มากกว่า Web Push Notification (มีผู้ต้องการเพียง 4.3%)

### แผนพัฒนาต่อในอนาคต

รายการต่อไปนี้ **ยังไม่ได้พัฒนาในเวอร์ชันปัจจุบัน** และวางไว้เป็นงานต่อยอด:

- **เชิญผู้ที่ยังไม่มีบัญชี** ด้วยอีเมลชวนสมัครและผูกสิทธิ์ให้อัตโนมัติ (Acceptance Criteria F-04 ข้อ II — ตอนนี้ต้องให้สมาชิกสมัครก่อนแล้วจึงเชิญได้)
- **หารเฉลี่ยอัตโนมัติ** ตอนแบ่งรายจ่ายให้สัตว์เลี้ยงหลายตัว (ตอนนี้ผู้ใช้กรอกจำนวนเงินแยกรายตัวเอง)
- **บีบอัดรูปใบเสร็จอัตโนมัติ** ก่อนอัปโหลด (Constraint ข้อ Storage Limit — ตอนนี้รับไฟล์ได้ถึง 50MB โดยไม่บีบอัด)
- **ให้หมวดหมู่ที่ผู้ใช้สร้างเองเห็นเฉพาะเจ้าของและครอบครัว** (ตอนนี้หมวดหมู่ที่สร้างเองแสดงให้ทุกบัญชีเห็น)
- **แบ่งหน้าประวัติรายจ่าย** (ตอนนี้แสดง 100 รายการล่าสุด)

รายการที่พิจารณาแล้วว่า**ไม่อยู่ในแผนพัฒนา MVP** (future feature ที่ตัดออกจาก scope):

| Future Feature | เหตุผลที่ยังไม่ทำ |
|---|---|
| AI Receipt Scanner (OCR) | ต้องใช้เวลาเทรนโมเดล AI อ่านบิลภาษาไทย เกินขอบเขตเวลาของรายวิชา |
| Connect to Vet System | ต้องรอระบบฐานข้อมูลของคลินิกเปิด API มาตรฐานก่อน |
| GPS Pet Tracker Integration | ต้องพึ่งพาอุปกรณ์ IoT ภายนอกที่ผู้ใช้ต้องซื้อเพิ่ม |
| Pet-Friendly Location Community | เป็นฟีเจอร์เชิง Community/Location ไม่ตรงวัตถุประสงค์หลัก (Cost Tracking) |
| Social Login (Google) / 2FA | F-07 ใน Proposal ระบุเฉพาะ Email/Password และการรีเซ็ตรหัสผ่าน |

## ข้อจำกัดที่ทราบอยู่แล้ว (Known Limitations)

- อีเมลแจ้งเตือนทำงานเมื่อ deploy Edge Function และตั้ง `RESEND_API_KEY` แล้วเท่านั้น (ถ้ายังไม่ตั้ง ฟังก์ชันตอบ HTTP 501 และยังมี toast ในแอปตามปกติ)
- ไฟล์ใบเสร็จรับได้สูงสุด 50MB ต่อไฟล์ ถ้าเกินระบบจะปฏิเสธไฟล์ (ไม่มีการบีบอัดรูปอัตโนมัติ)
- แก้ไข/ลบรายการค่าใช้จ่ายได้ภายใน 30 วันหลังบันทึกเท่านั้น (ทั้ง Owner และ Co-caretaker)
- เมื่อดูแดชบอร์ดแบบ "ทุกสัตว์เลี้ยง" รายจ่ายที่แบ่งหลายตัวนับครั้งเดียวที่สัตว์เลี้ยงหลัก (กันนับซ้ำ)
- Leaked Password Protection ของ Supabase Auth ต้องใช้ Pro Plan ขึ้นไป จึงยังไม่ได้เปิด
